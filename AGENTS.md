# Dash

Repo: https://github.com/guided-traffic/dash — a start page for a Kubernetes cluster that finds its
apps through their Ingresses, the apps beside the bookmarks on a page of hairlines (ADR 0012). Two images — a Go backend (`backend/`, the API)
and a Go file server with the Angular bundle (`frontend/`) — both distroless; one Helm chart with two
Ingress objects, `/` to the frontend and `/api/` to the backend.
**Status: phase 2 (the dashboard: discovery, icons, bookmarks, badges, the page) is done,
released in 0.4.0; the plan holds only phase 1's open checks on GitHub** — the plan is
[docs/planning/project-plan.md](docs/planning/project-plan.md), the decisions are
[docs/adr/](docs/adr/README.md).

## Stack facts

- Backend: module `github.com/guided-traffic/dash/backend`, Go 1.27.3. Spec-first: the OpenAPI 3.1
  document in `backend/api/`, oapi-codegen's strict server, kin-openapi validation, RFC 9457 problems
  through `backend/internal/problem`. Configuration: `DASH_CONFIG`, `DASH_LISTEN_ADDR`,
  `DASH_LOG_LEVEL` and one strict YAML file (no keys yet). `/readyz` turns ready once the Kubernetes
  API server answered.
- Frontend: Angular 22.2 in `frontend/`, standalone, zoneless, signals, vitest on jsdom,
  angular-eslint, **no component library**; the client generated by ng-openapi-gen into
  `src/app/api/` (never edited); neutral tokens and four self-hosted faces (ADR 0012); the colour scheme
  stored as `dash.theme`.
  Its image's server is `frontend/server`, a Go module of the standard library only.
- Chart: `deploy/helm/dash/`. Both pods run as 65532, read-only, no capabilities; the frontend mounts
  no ServiceAccount token. Annotations of the product are `dash.gtrfc.com/*` only (ADR 0010).

## Testing

`make` is the entry point, from the repository root ([ADR 0003](docs/adr/0003-test-and-ci-policy.md)).

| Tier | Target |
|---|---|
| Go unit, both modules | `make test-unit` |
| Backend integration (envtest) | `make test-integration` |
| Frontend unit | `make frontend-test` |
| Static analysis | `make lint cyclo gosec vuln`, `make frontend-lint` |
| Chart | `make helm-lint helm-template helm-unittest helm-kubeconform` |
| Images | `make docker-build` (proves no shell) |
| End to end | `make e2e` |

No `-short`, no skip on a missing dependency; a fix comes with the test that failed without it.
Every CI job is in `semantic-release`'s `needs:`.

## Conventions that bite

- Conventional commits, **no apostrophe anywhere in a commit message**.
- Generated code is committed and written only by `make generate` / `make frontend-generate`.
- Never read or write `~/.kube/config`: clusters are the e2e cluster's file under `.cache/kind/`.
- Never run Helm, kind or kubeconform from the PATH; the Makefile builds the pinned ones into `bin/`.
- Never commit or push without the owner's permission.
- Separate verified from unverified in every report.
